Compito: Configurazione per-scenario degli strumenti (Tools Config)
Obiettivo

Introdurre un file di configurazione per ogni scenario che definisca gli strumenti disponibili (tool) nello scenario stesso, in modo analogo a tutorial.txt.

Il file di configurazione dello scenario deve essere:

dichiarativo

selezionato da home_config.txt

estendibile (icone, cursori, nomi, numero strumenti variabile)

1. Selezione del file di configurazione scenario

Nel file home_config.txt, per ogni scenario deve essere possibile indicare esplicitamente il file di configurazione associato.

Esempio:

Scenario=scenes/Manutenzione_Elettromandrino
Tutorial=scenes/Manutenzione_Elettromandrino/tutorial.txt
Configuration=scenes/Manutenzione_Elettromandrino/config.txt


Comportamento richiesto:

Alla selezione/caricamento dello scenario, il sistema deve caricare anche config.txt

Il caricamento avviene prima dell’inizializzazione UI degli strumenti

Se Configuration= non è presente → fallback a configurazione di default (hardcoded o globale)

2. File config.txt – Struttura iniziale

Il file config.txt definisce gli strumenti disponibili nello scenario.

Formato consigliato: INI-style, coerente con tutorial e sistemi esistenti.

Esempio minimo
[Tools]
Tool=ChiaveBrugola
Tool=ChiaveInglese
Tool=Mano
Tool=AriaCompressa

3. Definizione completa di uno strumento

Ogni tool deve poter definire:

Nome logico (usato nei tutorial: Utensile=)

Icona UI

Cursore (anche animato / multi-frame)

Tipo puntatore (fallback)

Eventuali metadati futuri

Esempio esteso
[Tool:ChiaveBrugola]
Label=Chiave a brugola
Icon=utilimages/chiave_brugola.png
Cursor=cursor/chiave_brugola/
Type=tool

[Tool:AriaCompressa]
Label=Aria compressa
Icon=utilimages/aria.png
Cursor=cursor/aria/
Type=tool

[Tool:Mano]
Label=Mano
Icon=utilimages/mano.png
Cursor=cursor/mano/
Type=hand

4. Asset consentiti

Vincoli chiari da rispettare nel parser:

Icone

Path relativo

Devono risiedere in:

/utilimages/


Cursori

Statici o multi-frame

Devono risiedere in:

/cursor/


Se directory → cursore animato

Se file singolo → cursore statico

5. Integrazione con il sistema esistente

Il coder deve:

Estendere il loader di scenario per:

leggere Configuration=

parsare config.txt

Registrare i tool in un ToolRegistry (nuovo o esistente):

indicizzati per ToolId

accessibili da:

UI strumenti

parser tutorial (Utensile=)

Agganciare la UI:

mostrare solo i tool definiti nello scenario

ordine = ordine di dichiarazione in [Tools]

Validazione:

warning console se:

icona mancante

cursor path invalido

tool usato nel tutorial ma non definito in config

6. Requisiti di compatibilità

Nessun breaking change:

Tutorial esistenti senza config.txt devono continuare a funzionare

Se Utensile=X non è definito in config:

fallback a tool di default

warning console (non errore bloccante)

7. Esempi di variabilità supportata

Lo stesso scenario deve poter usare configurazioni diverse come:

[Tools]
Tool=Lubrificante
Tool=Straccio
Tool=Mano
Tool=Martello
Tool=Calibro


con asset completamente differenti, senza modificare codice JS.

Deliverable attesi dal coder

Parser config.txt

Integrazione con home_config.txt

Registry strumenti runtime

UI aggiornata
